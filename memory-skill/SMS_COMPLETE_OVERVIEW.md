# Smart Memory System (SMS) — 总览

> 一个为 AI Agent 设计的持久记忆系统。
> 解决"每次会话都失忆"的问题——让 Agent 记住该记住的，忘掉该忘掉的。

---

## 核心理念

**全离线运行。** 不需要网络、不需要数据库、不需要向量服务。

Smart Memory System 的运行时依赖只有两样：

| 依赖 | 用途 | 是否可选 |
|------|------|---------|
| **Node.js 18+** | MCP 服务器（server.js） | 只用 compress.py 则不需要 |
| **Python3** | compress.py 压缩引擎 | 只用 MCP 检索则不需要 |
| **其他** | 无 | — |

没有 Chroma、没有 SQLite、没有 LLM 运行时、没有外部 API。SMS 的压缩不调用任何 AI——纯文件 stat + 字符串操作，<1秒完成。

---

## 这是什么

SMS 是一套**纯文件化的记忆架构**，不依赖任何外部服务（向量库、数据库、LLM 运行时），只依赖 JSON 文件和一套压缩脚本。

让 Agent 能：

- **跨会话记住知识** — 上次聊过的知识点这次还能引用
- **分级存储** — 高频的不丢、低频的不占空间
- **跨 Agent 共享** — 通过 Git 仓库，不同电脑/不同 Agent 可以同步记忆
- **永不丢失** — 全量 raw 日志保底

---

## 相比 claude-mem 的核心优势

| 维度 | claude-mem | SMS v3 |
|------|-----------|--------|
| **依赖** | SQLite + Chroma 向量库 + Node.js | **纯 JSON + Python3** |
| **可读性** | 二进制向量，不可读 | **记事本打开，人类可读** |
| **Token 开销** | 每次加载 top-N obs（不稳定） | **Hot 层恒定 ≤20 条** |
| **运行速度** | 调用 LLM 做压缩（秒级） | **文件 stat + 字符串操作（毫秒级）** |
| **检索精度** | 向量相似度模糊匹配 | **fingerprint 精确匹配** |
| **离线可用** | ❌ 需要向量库在运行 | ✅ cat 就能看 |
| **协作共享** | 单机 | **Git 同步，多人跨机** |

## 版本演进

### v1 — 基础 MCP 桥

一个简单的 MCP 服务器，把文件系统暴露给 Claude Code。记忆管理全靠手动。

### v2 — 写入前查重 + 命中考勤

引入了 fingerprint 去重机制、hit_count 追踪、score 排序。解决了**反复记同一件事**的问题。

### v3 — 三层分级存储（当前版本）

引入了 raw 日志（全量）→ 日文件（去重）→ consolidated（压缩）的三层结构。

## claude-mem vs SMS v1/v2/v3 对比表

### 1. 架构对比

| 特性 | claude-mem | SMS v1 | SMS v2 | SMS v3 |
|------|-----------|--------|--------|--------|
| 捕获方式 | 系统级钩子，全量 | 手动写文件 | 实时判断，按量记 | **全量 raw + 智能分级** |
| 存储引擎 | SQLite + Chroma | 纯 JSON | 纯 JSON | **三层 JSON** |
| 检索方式 | 向量语义搜索 | 无 | fingerprint 精确 | **fingerprint + title + raw 回溯** |
| 压缩机制 | LLM 语义摘要（秒级） | 无 | hit_count 排序 | **文件 stat + 分组合并（毫秒级）** |
| 跨 Agent | ❌ 单机 | ❌ 单机 | ✅ Git 同步 | ✅ **Git 同步 + author 追踪** |
| 外部依赖 | Chroma + SQLite + Node | Python3 | Python3 | **Python3（最少）** |

### 2. 性能对比

| 指标 | claude-mem | SMS v1 | SMS v2 | SMS v3 |
|------|-----------|--------|--------|--------|
| 每次压缩耗时（500条） | ~30-60s | N/A | ~0.3s | **~0.2s** |
| 冷门条目日常 Token | 全量加载 | 全量 MD | Hot 层 20 条 | **Hot 20 条 + title_only 省 90%** |
| 一年后存储 | ~4MB | ~200KB | ~200KB | **~1MB（含 raw 全量）** |
| 检索速度（一年后） | 向量搜索 ~50ms | 读全部文件 ~500ms | 扫 auto/ ~50ms | **consolidated 1文件 ~1ms** |
| 模糊回忆能力 | ✅ 强 | ❌ 无 | ⚠️ tag 命中 | ✅ **title + raw** |
| 精确命中率 | ⚠️ 中等 | ✅ 需要手写 | ✅ fingerprint | ✅ **fingerprint** |
| 离线查看 | ❌ | ✅ cat | ✅ cat | ✅ **cat** |

### 3. Token 消耗对比（典型一天）

| 场景 | claude-mem | SMS v1 | SMS v2 | SMS v3 |

| 10 次搜索 | ~25,000t | N/A | ~700t | **~710t** |

| **年总计** | **~9,782,000t** | 不可控 | **~766,500t** | **~605,900t** |

### 4. 优缺点总结

| 系统 | ✅ 优点 | ❌ 缺点 |
|------|--------|--------|
| **claude-mem** | 全量捕获，什么都记；模糊回忆能力强 | 依赖向量库，不可离线；token 消耗大；压缩慢（秒级）；每次返回内容不稳定 |
| **SMS v1** | 零依赖，纯文件 | 无去重、无搜索、无压缩——全靠手动 |
| **SMS v2** | fingerprint 去重精确；hit_count 自动排序；零依赖；token 恒定 | 无全量保底；冷门条目会彻底丢失；不支持模糊回忆 |
| **SMS v3** | 全量 raw 保底 + 三级检索；title_only 极高压缩比；dirty check 0.001s 跳过；Git 协作 | 全量 raw 日志需额外 800KB/年；模糊回忆靠 title 命中——不命中的就真没了 |
| **SMS v4** | FTS5 全文搜索（CJK/ASCII 分词）；全自动压缩（60s cron + midnight）；CLAUDE.md 自动记录规则；零费用压缩 | 同上 + FTS5 需要 SQLite（Python 内置） |


### 5. 垃圾话过滤对比 — claude-mem 防漏，SMS 防脏

两种系统过滤垃圾信息的哲学完全不同，不是哪个更好，而是取舍不同：

| 场景 | claude-mem（防漏） | SMS v1 | SMS v2 | SMS v3 |
|------|-------------------|--------|--------|--------|
| **核心理念** | 全量捕获 → AI 压缩过滤 | 无过滤，全手动 | 写前判断，**不记垃圾** | **raw 全量 + consolidated 精筛** |
| **"hi"、"好的"、"谢谢"** | 进 obs → LLM 压缩时自然消失 | 全记 | **根本不进文件系统** | **raw 里躺着，不影响检索** |
| **闲聊中有用的信息** | 进 obs → LLM 可能发现也可能漏 | 靠手动甄别 | ✅ **即时判断，发现 value 就记** | ✅ **raw 全量 + 有价值才进 consolidated** |
| **纯废话（"今天吃啥"）** | 进 obs → LLM 过滤掉 | 看心情 | ❌ **根本不记** | ❌ **不进 consolidated，但 raw 里可见** |
| **三个月后回头看的重要片段** | ✅ LLM 当年没发现不重要，obs 还在 | ❌ 没手写就没了 | ❌ 没记就没了 | ✅ **raw 日志永远在，还能翻** |
| **存储效率** | 100% 垃圾话也占 obs 空间 | 全靠自觉 | **零垃圾，最小存储** | **垃圾话占 raw（50B/条），不影响 consolidated** |
| **检索噪音** | ⚠️ 每次搜索都可能翻出废话 | 噪音少（因为记的少） | ✅ **检索极干净** | ✅ **consolidated 检索极干净** |
| **一句话总结** | **CCTV 监控** —— 全录了，回放时 90% 是垃圾 | 纸质日记 | **助理笔记** —— 只记重点 | **监控 + 助理** —— raw 全录，consolidated 只记重点 |

### 6. 离线能力对比

| 场景 | claude-mem | SMS v3 |
|------|-----------|--------|
| **运行时联网** | ✅ 需要（向量库服务） | ❌ **完全不需要** |
| **首次安装后离线** | ❌ 每次启动依赖 Chroma | ✅ **永远离线可用** |
| **离线查看记忆** | ❌ 需 Web UI + 网络 | ✅ **cat / 记事本直接打开** |
| **远程服务依赖** | Chroma + SQLite | **无** —— Node.js + Python3 即可 |
| **断网后功能** | ⚠️ 搜索、写入全挂 | ✅ **一切正常（git 同步除外）** |
| **数据迁移** | 需导出向量库 | ✅ **拷走 JSON 文件夹就行** |
| **适合场景** | 有网络服务的团队环境 | **离线本地、内网、单机** |

### 7. 选择建议

| 如果你需要... | 推荐 |
|--------------|------|
| 最省 token、最低成本 | **SMS v3** |
| 什么都能回忆起来（哪怕模糊） | **claude-mem** |
| 完全离线、零依赖 | **SMS v3** |
| 多人共享知识库 | **SMS v3（Git 同步）** |
| 机器人级别的全量日志审计 | **claude-mem** |
| 快速部署、不想折腾数据库 | **SMS v3** |

## SMS v3 数据流（一张图）

```
会话中产生知识点
       │
       ├──→ auto/raw/*.raw.json   ← 🥉 全量最小格式（50B/条，永不删）
       │
       ├──→ auto/*.json            ← 🥈 当天完整 detail（含 tags）
       │
       └──→ compress.py 定时触发
                │
                ├── 1. dirty check（stat 比较，0.001s 跳过）
                ├── 2. 读取 raw + auto + 旧 consolidated
                ├── 3. fingerprint 分组 → 去重合并
                ├── 4. score 重算 → tier 分配
                ├── 5. 冷门条目 → title_only
                └── 6. 写 consolidated.json ← 🥇 最高优先级
```

**一句话总结：claude-mem 是 CCTV，SMS 是助理笔记。CCTV 不会漏掉任何东西，但你要从 90% 的垃圾里翻出 10% 有用的。助理笔记干净利落，但助理觉得不重要的事，笔记上就没有。SMS v3 结合了两者：raw 日志当 CCTV 全录，consolidated 当助理笔记只记重点。**
