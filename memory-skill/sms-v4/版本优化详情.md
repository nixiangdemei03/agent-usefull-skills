# SMS v4 版本优化详情

## v3 — 压缩引擎全面升级

- **优化时间：** 2026-06-05
- **schema 版本：** 4.0

### 优化总结

#### 1. 评分公式重构
- **旧：** `score = hit_count × recency_factor`（七档阶梯，有跳跃）
- **新：** `score = I × e^(-λt) × log(f+1)`（连续函数，平滑衰减）
- λ = ln(2) / 21，统一半衰期 21 天
- 14/28/42 天改为纯文本活性标签，不再映射多个 λ 值
- importance 评分范围 1-5 → 1-10，`write_or_merge` 强制必传

#### 2. 交换式降级
- 旧 cap 溢出模式 → 交换式：Hot-bottom→Warm-front，Warm-bottom→Cold
- 降级数 = 升级数，数量对等
- Warm 饱和度 < 90% 时抑制 Cold 降级，仅做 Hot↔Warm 交换
- Warm 溢出时先接受再逐步消化

#### 3. 冷数据存储
- 废除 `full_detail.json` 单文件方案
- Cold detail → 直接写入 SQLite `memories` 表（O(1) 检索）
- `rebuild_fts.py` 优先保留 auto 文件中的完整 detail
- Cold 无上限

#### 4. 闲时检测
- 新增 `idle_monitor.ps1` 文件式守护，每 10s 写入空闲状态
- 6 次连续容错采样（60s）才确认为闲时，避免误触
- 保留原 `idle-monitor.ps1` Win32 API 方案
- `claude-sms.bat` 同时启动两套 monitor

#### 5. 向下兼容
- 旧条目（无 importance）自动补值：hot=7, warm=5, cold=3
- `server.js` search_memories 增加 SQLite 冷数据回溯

### 优化后提升

| 指标 | v2 | v3 | 提升 |
|------|----|----|------|
| 评分平滑度 | 阶梯跳跃 | 连续函数 | ✅ 无突变 |
| 半衰期 | 14 天 | 21 天 | ✅ 热度记忆延长 50% |
| 重要性精度 | 1-5 | 1-10 | ✅ 粒度翻倍 |
| Cold 检索 | full_detail.json 解析 | SQLite O(1) | ✅ 50MB 级时仍可用 |
| 闲时误触 | 1 次采样 | 6 次连续确认 | ✅ 防瞬时误触发 |
| Warm→Cold 条件 | 满 100 即踢 | ≥90% 饱和度 | ✅ 保护未满冷数据 |
| 降级逻辑 | cap 溢出 | 交换式对等 | ✅ 升降级数量一致 |
| 兼容性 | 无 | 旧条目补 importance | ✅ 平滑升级 |
