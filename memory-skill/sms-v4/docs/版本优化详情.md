## v4.05 — 强制降级: superseded 条目→cold + Hot 重填（2026-06-05）

### 改动清单

| # | 改动 | 涉及文件 | 说明 |
|---|------|---------|------|
| 1 | **compress.py superseded→cold** | `compress.py` | 压缩时自动将标记为 `superseded` 的条目强制降级到 Cold 层 |
| 2 | **Hot/Warm 重填** | `compress.py` | 被 superseded 腾出的空位由下一顺位的最高分条目填补，不浪费层级名额 |
| 3 | **title_only 同步** | `compress.py` | 强制降级同时标记 `title_only` 压缩详情，节省 consolidated 空间 |
| 4 | **cold 可还原** | — | `update_entry` 直接写 tier 即可恢复，superseded 标记不锁死 |

### 行为说明

```
压缩流程:
  1. 按 score 分 tier（hot 20 / warm 100 / cold）
  2. 交换降级（hot↔warm↔cold）
  3. ✅ 强制: superseded=true → tier=cold, title_only
  4. ✅ 补位: 从剩余条目最高分按序填满 hot 20 / warm 100
```

### 场景验证

测试通过（1 条旧 hot 条目标记 superseded → 强制 cold → hot 重填为 20 → warm 重填为 30 → 恢复后回滚）

## v4.03 — supersedes 机制 + 历史查询模式（2026-06-05）

### 版本背景

从 v4.02 到 v4.03 解决以下问题：
- 过时信息（改名/改配置）无法优雅取代旧记录，新旧信息同时出现造成混淆
- 搜索引擎默认返回所有结果包含已淘汰内容
- 无法按时间追溯历史变更

### 最终改动清单

| # | 改动 | 涉及文件 | 说明 |
|---|------|---------|------|
| 1 | **`write_or_merge` 新增 `supersedes` 参数** | `server.js` | 写入新条目时声明取代的旧条目 ID 列表 |
| 2 | **自动标记旧条目** | `server.js` | 新条目写入时自动将旧条目标记 `superseded: true` + 加 `superseded_by` 指针 |
| 3 | **默认过滤 superseded** | `server.js` | `get_context` 和 `search_memories` 默认不返回被取代的条目 |
| 4 | **历史查询模式** | `server.js` | 检测"以前"/"之前"/"原来"/"几月几号"关键词时自动解除过滤 + 按时间逆序 |
| 5 | **日期精确检索** | `server.js` | 用户问"2月""2026年2月"时按时间范围筛选 |
| 6 | **compress.py 同步** | `compress.py` | 压缩过程保留 supersedes 相关字段 |
| 7 | **CLAUDE.md 指南** | `CLAUDE.md.template` | supersedes 使用说明 |

### Bug 修复清单

| # | Bug | 修复方式 |
|---|-----|---------|
| 1 | `get_stats` hot/warm/cold 重复计数 | 改为互斥分类，每条目只计入一个 tier |
| 2 | `get_context` 使用静态 cache 导致数据不一致 | 全实时聚合并弃用 cache count |
| 3 | fingerprint 依赖 tags 导致去重失效 | 改为纯 summary 语义指纹，兼容旧指纹 |
| 4 | 系统自指事件写入记忆 | `write_or_merge` 增加 forbidden 模式过滤器 |
| 5 | `hit_memory` 不回写 score 和 tier | 三路回写：auto → consolidated → SQLite |
| 6 | `recalc_score` SQL 无 `last_hit` 列 | 全部改为 `timestamp` |
| 7 | `search_fts` 含数字报错 | MATCH 异常时降级为 LIKE 搜索 |

## v4.01 — 压缩引擎优化（2026-06-05）

### 版本背景

从 v4.00 到 v4.01 的迭代解决以下问题：
- 半衰期 14 天与旧评分公式 (`hit_count × recency_factor`) 在连续函数上不兼容
- Warm→Cold 降级只有 cap 溢出，没有饱和度门限
- Cold detail 丢失（`full_detail.json` 单文件膨胀风险）
- 闲时检测缺少真正的系统级空闲判定
- 旧条目无 importance 字段，评分无法区分重要性

### 最终改动清单

#### P0 — 核心逻辑

| # | 改动 | 涉及文件 | 优化点 |
|---|------|---------|--------|
| 1.1 | **半衰期 14→21 天，统一 λ**。14/28/42 改为纯文本标签，不再映射多条 λ | `compress.py` `server.js` | 评分函数连续平滑，无跳跃 |
| 2.1 | **Warm 饱和度门限**：≥90% 才做 Warm→Cold 降级，不足时只做 Hot↔Warm 交换 | `compress.py` Step 3 | 保护未满冷数据不被误踢 |
| 4.1 | **PowerShell 守护脚本 `idle_monitor.ps1`**：每 10s 写到文件，WSL 侧读取 | `scripts/idle_monitor.ps1` + `compress.py` | 真正的系统级空闲判定 |
| 4.3 | **容错采样**：连续 6 次（60s）空闲才触发，`.idle_counter` 计数器 | `compress.py` `check_idle_with_counter()` | 防瞬时无操作误触发 |

#### P1 — 显著改善

| # | 改动 | 涉及文件 | 优化点 |
|---|------|---------|--------|
| 3.1 | **废除 `full_detail.json`**，Cold detail → 直接写入 SQLite `memories` 表 O(1) 检索 | `compress.py` Step 4 + `rebuild_fts.py` | 规模可控，50MB 级仍可用 |
| 6.1 | **search_fts 直接带 Cold detail**；search_memories 增加 SQLite 回退拉取 | `server.js` | 冷条目检索无额外延迟 |

#### P2 — 锦上添花

| # | 改动 | 涉及文件 | 优化点 |
|---|------|---------|--------|
| 2.2 | **Warm 溢出消化**：超额部分先接受再逐步消化 → 下次交换恢复 | `compress.py` Step 3 | 边界行为稳定 |
| 5.2 | **旧条目补 importance**：hot=7, warm=5, cold=3 | `compress.py` `get_importance_for_old_entry()` | 平滑升级兼容 |

### 优化后提升指标

| 指标 | v4.00 | v4.01 | 提升 |
|------|-------|-------|------|
| 评分平滑度 | 阶梯跳跃 | 连续函数 `e^(-λt)` | ✅ 无突变 |
| 半衰期 | 14 天 | 21 天 | ✅ 热度记忆延长 50% |
| 重要性精度 | 1-5，optional | 1-10，**required** | ✅ 粒度翻倍，不再遗忘 |
| Cold 检索 | `full_detail.json` 全量解析 | SQLite `memories` O(1) | ✅ 50MB 级仍可用 |
| 闲时检测 | 无真正系统级检测 | `GetLastInputInfo` + 6 次采样 | ✅ 精确到鼠标+键盘 |
| Warm→Cold 条件 | 满 100 即溢出 | ≥90% 饱和度门限 | ✅ 保护未满冷数据 |
| 降级逻辑 | cap 溢出式 | 交换式对等 | ✅ 升降级数量一致 |
| 兼容性 | 无旧条目处理 | 自动补 importance | ✅ 平滑升级 |

## v4.00 — 初始发布（2026-06-04）

> 初始架构：三层存储架构 + 基础压缩 + FTS5 搜索。

| 特性 | 说明 |
|------|------|
| 存储架构 | raw（全量）→ auto（日去重）→ consolidated（跨天压缩） |
| 评分公式 | `score = hit_count × recency_factor`（七档阶梯） |
| 重要性 | 1-5，optional |
| Hot 层 | 20 条自动注入上下文 |
| Warm 层 | 100 条搜索可见 |
| Cold 层 | title_only，detail 丢失 |
| 压缩触发 | cron 每分钟 `--auto`（无真正闲时检测） |
| 搜索 | FTS5 全文索引（SQLite） |
| 去重 | fingerprint 分组合并 |
