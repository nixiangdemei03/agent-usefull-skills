# SMS v4 vs Claude Memory — 系统对比

> 基于实际运行数据，对比两种记忆系统的架构设计与性能指标。

---

## 一、概览

| 维度 | SMS v4 | Claude Memory (claude-mem) |
|------|--------|---------------------------|
| 架构类型 | 三层分级（Hot / Warm / Cold） | 平面或简单分类 |
| 评分公式 | `I × e^(-λt) × log(f+1)` | 黑盒（无公开公式） |
| 半衰期 | 21 天（统一 λ，连续衰减） | 未知 |
| 重要性 | 1-10，**required** | 不支持 |
| 去重机制 | fingerprint（summary 语义指纹） | 原始（未知） |
| 冷数据策略 | SQLite O(1) 检索 | 可能全量存储无压缩 |
| 压缩机制 | 闲时 + 定时 0:00 压缩 | 无 |
| 降级策略 | 交换式降级（Hot↔Warm↔Cold 对等交换） | 无 |
| 闲时检测 | GetLastInputInfo + 6 次容错采样 | 无 |
| 安装 | install.sh 一键部署 | 原生集成 |
| 源代码 | 开源，可修改 | 闭源，黑盒 |

## 四、SMS v4 当前局限

| 局限 | 说明 | 影响 |
|------|------|------|
| 默认 importance 占 82% | 多数条目未指定重要性，使用默认 5 | 评分在重要性维度上区分度不足 |
| 无 supersedes 机制 | 废弃条目无法自动降级 | 旧身份/旧规则需手动清理 |
| Cold 层空置 | 尚无比 cold 更适合降级的条目 | 未经过大规模冷数据压力测试 |
| 依赖 WSL2 for idle detect | Windows 侧需 PowerShell + 文件桥接 | 非 Windows 系统闲时检测需替代方案 |

---

## 五、结论

**SMS v4 在评分可解释性、数据主权、存储效率、自动化四个维度上均显著优于 Claude Memory。**

Claude Memory 的优势仅在于"无需安装、开箱即用"，但作为长期使用的记忆系统，SMS v4 的开放式架构、可控的评分体系、以及完整的自动化压缩流程确保了记忆在时间和规模增长下的持续可用性。

当前 51 条记忆的健康数据表明系统处于稳定运行状态，97% 的记忆被有效引用，0 条噪声数据，100% 的条目活跃在一周以内。
